# Безопасность публичного набора

Этот репозиторий содержит обезличенные шаблоны, не backup рабочего экземпляра n8n.

## Что удалено

- Telegram bot token из четырёх HTTP URL.
- Личные Telegram ID менеджера из отправок и проверки ролей/callback.
- 107 node credential references с исходными именами и ID.
- Исходные workflow IDs, instance metadata, webhook IDs, version metadata и tags.
- Pinned data и потенциальные runtime payloads: публичные `pinData` пусты.

В публичных workflow оставлены выражения конфигурации и явные placeholders. Все workflow неактивны. Оригинальные приватные файлы не менялись и не включены в набор.

## Что сюда нельзя добавлять

`.env`, заполненные credentials, дампы клиентских строк, SQL с hardcoded secrets, executions/error logs, личные переписки, необработанные скриншоты, исходные видео и `.tsrct`. `.gitignore` - дополнительная защита, а не очистка уже закоммиченных данных.

Обложки - иллюстрации. Скриншоты выбраны без имени аккаунта, телефона, client/chat IDs и credential values. Непрерывный финальный ролик нужно проверить отдельно; он не входит в репозиторий.

## Токены и история Git

Если секрет когда-либо попал в чужие руки, remote, публичный файл или историю Git, сначала отзовите/перевыпустите его и обновите зависимости. Удаление строки не аннулирует токен. Очистка истории не заменяет ротацию.

Набор подготовлен в новой папке без Git-истории. Это не аудит какого-либо ранее опубликованного remote-репозитория. Не копируйте `.git` из приватного проекта и не загружайте родительскую папку подготовки целиком.

## Runtime

Формат Telegram Bot API включает токен в URL. Даже если JSON читает токен из защищённой конфигурации, URL может оказаться в execution/error logs. Ограничивайте доступ, retention и экспорты. Настройка `$env` зависит от security policy сервера; не ослабляйте её автоматически.

Error Alerts может передавать текст исходной ошибки. В production нужно отдельно проверить маскирование секретов и ПД в этих сообщениях. Наличие Error Trigger не означает безопасную обработку всех ошибок.

## Данные реальных клиентов

Демо использует тестовый сценарий. Для внедрения отдельно проверяются требования к ПД, локализации/трансграничной передаче, правам доступа, consent/retention и используемым внешним сервисам. Этот публичный набор не подтверждает соответствие production требованиям законодательства.

## Проверка перед commit

Из корня набора:

```bash
python scripts/check_public.py
git status --short
git diff --cached --stat
```

Сканер - эвристика: он не распознаёт все возможные секреты, не делает OCR и не заменяет ручную проверку новых файлов. Особое внимание - SQL function bodies, JSON parameters, README-ссылки и изображения.

Если нашли проблему, сообщите автору приватно через [публичный контакт](https://t.me/eaojjm), без публикации секретного значения.
